The actual init event had empty skills/slash-command lists, the sole MCP tool, a built-in agent catalog, and two active plugins: `cc-plugin-agents-md` and `cc-plugin-plugin-authoring`. The pinned executable's `lCe` function registers eleven built-in plugins. Its `qee` function reads the `enabledPlugins` setting keyed by canonical plugin name plus `@builtin`; absent overrides fall back to each plugin's default, which can be enabled. An empty settings map therefore did not disable these plugins. The adapter now explicitly sets all eleven pinned registry entries to false. These settings are included in the qualification binding. The parser still rejects any nonempty active plugin list; it does not merely ignore the observed plugins. A fixture copied only the sanitized shape of the observed init event: it is rejected with the two active plugins and accepted with an empty plugin list. ### Phase 6: serial HTTP admission and rejection evidence

The first four consumed Opus campaign cells remain immutable. Cells 3 and 4 stopped with a transport boundary rejection, completed observed requests and settled tool cleanup. Their adapter omitted the fatal reason and rejection records, so the exact historical rejection category is unknown. No retrospective claim assigns those cells to a concurrency race.

An offline fake-server reproduction established a real defect in the old admission rule: a response sent `message_stop` but kept its HTTP stream open before EOF; a valid following request received HTTP 503 with `concurrent_request_rejected` while only the first request had reached the upstream. This overlaps response cleanup with the next request, without requiring concurrent upstream inference. The versioned `serial-admission-v2` policy permits one pending request to wait for the previous handler to finish, bounded by 15 seconds and the invocation deadline. Only one upstream request is active at a time. A second waiter is rejected, shutdown cancels pending admission, and every admitted request still passes the exact model/effort/OAuth/tool checks before forwarding.

Invocation receipts now retain allowlisted `transport_diagnostics.fatal` and rejection categories, whether an upstream request was sent, and timestamps. Unknown exception text becomes `invalid_transport_data`; request bodies, authorization headers and arbitrary exception strings are excluded. Per-request admission wait is recorded. This is a new instrumentation binding requiring fresh qualification and an explicit campaign epoch transition; it does not rewrite or retry consumed cells. No model calls were used for reproduction or implementation.
