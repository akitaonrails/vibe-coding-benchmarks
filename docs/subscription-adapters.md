# Subscription adapters: capability research and implementation gate

Research: 2026-10-10. This document proposes implementation; no Kimi/GLM inference or coding trial was launched during this research. Installed metadata and pinned upstream source support an MCP-only design. They do not yet establish a qualified live adapter, remaining subscription allowance, or verified token accounting.

The first authorized matrix is ledger-engine × seven languages × Kimi K3/OpenCode GLM5.3 × T0/T1 × two replicates: 56 attempts, each retaining the first handoff and at most two eligible short reactivation continuations. Compilation, private grading, and analysis remain separate from model interaction. After that matrix, inspect Claude/Codex availability and, if available, run the same matrix with Opus5.5 medium and Sol medium. Do not probe those providers early or substitute another model silently.

## Isolation design

Use a trusted, controller-owned stdio MCP server exposing exactly `sandbox_shell(command, timeout_seconds)`. It forwards into the already bounded, offline `DockerWorker`; the agent never receives Docker socket access, arbitrary container identifiers, host filesystem tools, private cases, references, or grading results. The parent controller owns the worker across the initial turn and any eligible continuations. Each restarted CLI's MCP child reconnects to that same trusted controller through a private authenticated local channel. Only that parent dispatches `worker.execute`; it serializes calls and performs cleanup/export before checkpointing.

The bridge accepts no alternate root/container, and exposes neither MCP resources nor prompts. It sanitizes its subprocess environment and does not pass provider credentials into candidate execution. Tool arguments remain untrusted: invalid ordinary schema returns a recoverable failed result without execution; unknown capabilities, cross-session identities, unexpected server methods or failed isolation checks terminate the attempt as infrastructure-invalid. Token/time costs of rejected calls are still recorded.

Kimi has two independent filters: a global nonempty allowlist and a custom agent's tool list. Set both to the exact benchmark MCP name, for example `mcp__langbench__sandbox_shell`; use an explicit agent file with a self-contained system prompt and no delegation tools. The source composes policies and registers an execution-time guard, so the filter is not merely descriptive. Empty **global** `tools.enabled` does not disable tools; a literal `*` denylist does not mean deny all. Disable skills/plugins/hooks/watchers/background steering, set a dedicated empty skills directory, and create the session outside all repositories. A custom profile is bound at session creation and restored on explicit resume. [Agent profiles](https://moonshotai.github.io/kimi-code/en/customization/agents.html), [MCP configuration](https://moonshotai.github.io/kimi-code/en/customization/mcp.html), [pinned policy implementation](https://github.com/MoonshotAI/kimi-code/blob/f67e6398fb3210ad8ace970e2dfd5bcc984ed61f/packages/agent-core-v2/src/agent/toolPolicy/toolPolicyService.ts).

OpenCode should use a clean home and XDG config/data/cache/state, an empty working directory outside the checkout, `--pure`, disabled auto-updates/sharing/snapshots/LSP/formatters, and only the selected provider. Its permissions start with `"*":"deny"`, followed by allowance for the exact benchmark MCP tool after observing its actual registered name. Keep the agent's own permission layer equally restrictive; disable agent delegation. The pinned permission implementation hides denied tools, including aliases for edit and MCP-resource reads. A custom config path alone is insufficient: configs merge with global/project sources, and `/etc/opencode` managed policy must also be inspected. Unsupported isolation flags cannot be presumed effective. [Configuration precedence](https://docs.opencode.ai/docs/config/), [permissions](https://docs.opencode.ai/docs/permissions/), [MCP support](https://docs.opencode.ai/docs/mcp-servers/), [pinned tool visibility](https://github.com/anomalyco/opencode/blob/aec0b9a6d8898f68f923aaf08b7306d931fd9d76/packages/opencode/src/permission/index.ts).

The provider CLI is trusted orchestration, not a candidate shell. Native-tool denial must be demonstrated before inference through resolved configuration/tool inventory and protocol tests, then challenged in a harmless live probe. If the installed CLI cannot enforce this boundary, fail closed; do not compensate with a prompt requesting good behavior.

## Authentication and process lifecycle

Kimi's `KIMI_CODE_HOME` relocates its configuration, logs, sessions and credentials, but generic shared agent resources may still be discovered elsewhere. Keep all newly written configuration/session state temporary and use a self-contained profile/empty skills directory. OpenCode's existing environment-referenced Z.ai credential can be passed only to the provider process; no other provider credentials or inherited agent environment are required. [Kimi data locations](https://moonshotai.github.io/kimi-code/en/configuration/data-locations.html).

**Kimi refresh requires deliberate integration.** The inspected credential metadata reports a 900-second access-token lifetime. Copying an OAuth file into an independent home is unsafe for a long attempt: the pinned OAuth manager explicitly coordinates rotating refresh tokens using `{configDir}/oauth/<provider>.lock` plus storage rereads. Do not create an independent refresh chain or disable locks. Implementation should preserve the original credential store and canonical lock namespace while isolating every other setting, for example through narrowly bound credential/lock directories whose resolved paths are verified equal. Normal provider-managed refresh is distinct from rewriting global config. Test lock identity with fake credentials first; never print, export, commit or expose real auth files through MCP. If this cannot be established, the Kimi adapter is not ready for a long coding attempt. [Pinned OAuth coordination](https://github.com/MoonshotAI/kimi-code/blob/f67e6398fb3210ad8ace970e2dfd5bcc984ed61f/packages/oauth/src/oauth-manager.ts).

Start with existing CLI streaming modes to minimize new protocol surface: Kimi `-p ... --output-format stream-json -m kimi-code/k3`, then explicit `-S SESSION`; OpenCode `run --format json --model zai/glm-5.3 --agent benchmark`, then explicit `--session SESSION`. Kimi's profile flag applies only when creating the session, not resuming it. ACP is an available alternative for cancellation/model selection, but it is not itself a sandbox; advertising no client filesystem/terminal capabilities and supplying only the MCP bridge is mandatory if chosen. [OpenCode CLI](https://docs.opencode.ai/docs/cli/), [Kimi ACP reference](https://github.com/MoonshotAI/kimi-code/blob/f67e6398fb3210ad8ace970e2dfd5bcc984ed61f/docs/en/reference/kimi-acp.md).

Use monotonic deadlines, bounded stdout/stderr and JSON frames, per-process-group termination and child cleanup. At a normal handoff, terminate/settle all candidate commands, export/hash the snapshot, then evaluate the frozen visible-handoff assistance rule, independently of private correctness. Never feed a private grade back. Quota exhaustion stops collection without retries, provider fallback or a hidden replacement attempt; retain every failed/partial attempt. Qualification costs and setup incidents are stored separately from candidate coding effort.

## Conditional assistance contract

The new matrix follows [the effort protocol](matrix-effort-protocol.md), superseding unconditional two-nudge collection only for new attempts. Freeze initial 900-second and continuation 180-second maximum windows; actual work and continuation counts vary. Each adapter must return the exact terminal assistant text, its session identity and transport termination status.

Proposed deterministic policy `terminal-status-v1`: the common initial prompt requests exactly one final line `BENCHMARK_STATUS: COMPLETE`, `BENCHMARK_STATUS: INCOMPLETE`, or `BENCHMARK_STATUS: BLOCKED`. A single recognized final-line marker is a self-report, never a correctness judgment. COMPLETE closes collection. INCOMPLETE or BLOCKED after a normal handoff permits the next fixed generic reactivation, up to two total. Missing, malformed, duplicate or conflicting markers close collection as `handoff_status_unknown` without an automatic nudge; preserve the text and uncertainty. Timeouts, quota stops and fatal adapter errors do not qualify. Do not introduce a separate judge model or infer eligibility from hidden failures. Qualify marker extraction on real CLI terminal output before freezing this policy.

Fixed reactivation text: “Continue the existing task using the available sandbox tool. No additional permission is needed for edits within the permitted workspace. Finish with the requested status marker.” Record eligibility status, reason, exact prompt, timestamps and all resulting work; a short prompt may cause substantial agent work. The adapter exposes terminal evidence; the separate controller owns the decision. No continuation is sent solely to match another attempt's iteration count.

Maintain an append-only operator-intervention ledger with actor, category (reactivation, toolchain/environment repair, technical guidance, direct source edit), reason, scope, timestamps, exact action/prompt or its retained-artifact hash, and before/after source hashes where relevant. Qualification/setup friction stays separate from coding effort. Guidance or direct repair creates an explicitly assisted treatment; it must not silently improve the primary attempt. Coordinating-agent work is AI/operator assistance, not observed human labor; unknown human hours remain unknown.

## Tokens, iterations and raw evidence

The reference harness at `~/Projects/llm-coding-benchmark/scripts/benchmark/runner.py` contains useful Kimi resume/export handling. Its token summation is a starting observation, not an accounting authority. It starts unrestricted host agents and uses permissive OpenCode settings; those parts must not be reused.

Kimi print events identify the session but do not themselves carry complete token totals in the inspected reference parser. Its local `agents/main/wire.jsonl` contains per-generation `context.append_loop_event` / `step.end` usage, whereas `usage.record` can be cumulative. Pinned source defines `inputOther`, `inputCacheRead`, `inputCacheCreation`, `output` as disjoint normalized fields. The Kimi mapping subtracts cached input from prompt tokens and currently sets cache creation to0; it also substitutes0 for missing native fields. Therefore report **CLI-normalized** usage with mapping provenance, not newly proven provider/billing totals or a reasoning breakdown that the format does not expose. Missing native evidence remains unknown. [Usage shape](https://github.com/MoonshotAI/kimi-code/blob/f67e6398fb3210ad8ace970e2dfd5bcc984ed61f/packages/kosong/src/usage.ts), [native mapping](https://github.com/MoonshotAI/kimi-code/blob/f67e6398fb3210ad8ace970e2dfd5bcc984ed61f/packages/kosong/src/providers/openai-common.ts).

OpenCode emits step-finish/message accounting. In 1.18.34 the normalization subtracts cache reads/writes from input and reasoning from output, while preserving a separate `total` when available. Thus do not apply Codex's reasoning-overlap rule or blindly add reasoning twice. Deduplicate stable message/part/request identities, reconcile per-step records against final session export, and distinguish request usage from session cumulative updates. Its normalization also defaults/clamps missing values; a zero does not prove the provider reported zero. Catalog dollar costs do not measure this subscription's marginal bill. [Pinned usage normalization](https://github.com/anomalyco/opencode/blob/aec0b9a6d8898f68f923aaf08b7306d931fd9d76/packages/opencode/src/session/session.ts), [step recording](https://github.com/anomalyco/opencode/blob/aec0b9a6d8898f68f923aaf08b7306d931fd9d76/packages/opencode/src/session/processor.ts).

Preserve per-model-request IDs, timestamps, token fields and accounting scope; per-tool exact name/arguments/command, bounded result, exit, termination, elapsed time and rejection status; and source digest before/after each quiescent tool call. Record changed-file hashes and optional bounded diffs to establish whether a command changed candidate source. A source digest change is evidence of a revision, not by itself an iteration or a successful repair. Retain raw traces so the later classifier can distinguish edit/build/test/runtime cycles, tool misuse, infrastructure failure and quota interruption. Tool calls must never be equated with iterations. Report initial, nudge1, nudge2, marginal continuation and total effort, including failed attempts. Each cell's language/test condition, seed, replicate, model, effort and CLI version remain attached to every event.

## Phase2 implementation and qualification sequence

1. Add provider-neutral adapter identity/receipt fields and a serialized MCP bridge to the existing collector. Add a separate conditional-assistance controller; preserve historical fixed-nudge behavior and receipts. Keep trusted grading ordering. No model-specific grade feedback or language-specific hints.
2. Write fake protocol tests for handshake, exact tool inventory, denied native calls, argument rejection, resume continuity, bounded streams, timeout/interrupt cleanup, duplicate/missing usage, late events, and auth refresh-lock identity. Capture a sanitized resolved configuration/tool manifest, without credentials.
3. Run a tiny fresh-session capability probe through each real subscription only after step2. Require a known command executed by the bridge to create a nonce under candidate `src/`, assert host/oracle canaries absent from the worker, and verify requests to use host read/shell/delegation are unavailable. Agent prose is not proof. Do not use a coding task for this probe.
4. Bind a passed qualification to executable hashes, provider/model/effort, tool/config hash, auth route type and worker environment. Separate the probe session from a fresh task session. Qualify explicit continuation and telemetry with two short turns before declaring the adapter ready.
5. Freeze the 56-cell plan and run sequentially with durable progress, infrastructure/quota stops and no silent replacements. Compiler/runtime installations, adapter development and qualifying probes stay outside measured candidate effort. Only after these cells finish consider the deferred Claude/Codex matrix.

Open items for the gate are live enforcement, Kimi refresh-store binding, effective GLM effort serialization, CLI usage completeness, and executable/provider pinning. No live success or available quota is claimed from configuration presence alone.
