# Adaptive Sol subscription adapter

Implementation status, 2026-10-11: `langbench/codex_subscriptions.py` provides `qualify_codex` and `run_codex`, exclusively for `gpt-6-sol` with `medium` effort through existing ChatGPT authentication. The account/catalog availability check is separate from live adapter qualification. No live inference was launched in this implementation lane. First-cohort receipts and task assets remain unchanged.

The adapter reuses the historical app-server protocol/capability checks, including no provider fallback, empty builtin environments, the sole dynamic `sandbox_shell`, disabled host tools and Code Mode's exact-source/structured-output qualification. It does not change the historical runner. A recording worker proxy hashes submitted source around each synchronous tool execution and retains command outcomes; rejected ordinary tool arguments remain recoverable while identity/capability violations stop collection.

Historical export is overridden to do nothing. A non-handoff closes the app-server process before capture; the controller can no longer dispatch queued candidate tool calls. `subscriptions.capture_invocation` then exports or recovers `DockerWorker(runtime='seven', retention='seal-v1')` source. Worker-retired sources retain the cutoff/writer-stop/seal timestamps and explicit terminal-sealed classification. Native transport/token completeness remains independent of artifact availability. Normal handoffs preserve the same thread for the existing visible-terminal adaptive policy; private grading follows closure of both model and worker contexts.

The qualification requires an exact Code Mode host-global probe, sandbox command/host-canary evidence, same-session continuation and complete native usage reconciliation. Its commitment binds source files, binary/companion identity, runtime, auth mode, model/effort and assistance policy. Failure is retained and does not authorize a coding attempt. After successful external qualification, `run_codex` freezes a manifest and collects all actual checkpoints through `assistance.collect`; there are no automatic qualification calls inside a coding attempt.

Usage is stored as `native_usage_reconciliation` per invocation and collection. The existing `appserver-response-v1` parser deduplicates explicit `rawResponse/completed` response IDs and reconciles native components with fresh-thread cumulative counters. Cached/reasoning components are subsets. Incomplete turns retain known subtotals without complete totals. The app-server trace exposes completed responses rather than an independently observable wire request-start inventory; response count must retain that scope. No synthetic Kimi/OpenCode request-record schema or fabricated normalized total is emitted. Reporting integration must consume this native structure explicitly.

Explicit recognized output-limit reasons are recorded as `completion_kind=model_output_limit`; terminal text is suppressed for assistance decisions so a length stop cannot request a nudge. Unrecognized/missing native reasons are not guessed from token counts. Native event schemas remain version-sensitive and require harmless live qualification before use.

Before every invocation, a non-inference `account/rateLimits/read` must explicitly report `ordinaryUsageAllowed:true`. False stops with quota before a turn starts; missing/failed evidence stops as infrastructure-invalid. Only the boolean is retained, never account IDs or credit payloads. An explicit false allowance notification during a turn is converted to quota before subsequent tool dispatch. No paid route, reset credit or fallback is selected.

Focused verification: 16 fake-only tests in `tests/test_codex_subscriptions.py` cover exact model/effort, source tracking/deferred export, timeout closure, explicit resume/markers, forbidden capabilities, recoverable arguments, quota, explicit length stop, cumulative/request usage, partial usage, account-event exclusion cross-turn/model mismatches, allowance denial and mid-turn allowance revocation. These tests neither start Docker nor contact a provider. Existing metrics and worker-retention tests are separate evidence; full adapter qualification and the later 28-cell matrix remain pending integration/review.

Qualification success is revoked on any teardown exception, even after all probes passed. Adapter and worker teardown failures are covered separately. Allowance preflight duration is recorded separately; a denied or unverifiable allowance starts no inference and contributes zero candidate-active seconds.
